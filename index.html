Not a wrapper. The forward pass, backward pass, SGD update, and even the ONNX protobuf encoder are hand-written in the repo. No ndarray, no burn, no autodiff — and the core crate has zero dependencies.

TROT is deliberately binary sentiment. The 3-channel spectrum and the multi-head router from earlier drafts remain conceptual extensions until a real version exists.

The model is the code

crates/trot-core/src/model.rs

This is the entire forward pass. No layer abstraction, no library call — one nested loop and a few scalar operations. If you can read a for loop, you can read the model.

model.rs · forward pass open exact lines ↗ 
pub fn forward(&self, x: &[f32]) -> Forward {
    let (h, v) = (self.hidden, self.vocab);
    let mut z1 = vec![0.0f32; h];
    for j in 0..h {
        let row = &self.w1[j * v..j * v + v];
        let mut acc = self.b1[j];
        for i in 0..v {
            acc += row[i] * x[i];
        }
        z1[j] = acc;
    }
    let hh: Vec<f32> = z1.iter().map(|&z| z.tanh()).collect();
    let mut z2 = self.b2;
    for j in 0..h {
        z2 += self.w2[j] * hh[j];
    }
    let p = sigmoid(z2);

The gradients are the code too

crates/trot-core/src/train.rs

Backpropagation here is a handful of multiplications. The chain rule is written out by hand, then applied to every parameter.

train.rs · one backward pass open exact lines ↗ 
pub fn backward(m: &Model, f: &Forward, y: u8) -> Gradients {
    let (h, v) = (m.hidden, m.vocab);
    let dz2 = f.p - y as f32;

    let mut w2 = vec![0.0f32; h];
    for j in 0..h {
        w2[j] = dz2 * f.h[j];
    }

    let mut w1 = vec![0.0f32; h * v];
    let mut b1 = vec![0.0f32; h];
    for j in 0..h {
        let dz1 = dz2 * m.w2[j] * (1.0 - f.h[j] * f.h[j]);
        b1[j] = dz1;
        let row = &mut w1[j * v..j * v + v];
        for i in 0..v {
            row[i] = dz1 * f.x[i];
        }
    }
    // ...
}
It is tested, not just displayed. The Rust test suite includes a gradient check that compares every analytic gradient against a central-difference numerical approximation — the same test you would write in a numerical methods course.

let tanh = node("Tanh", &["z1"], &["h"], &[]);

The encoder is ~200 lines of hand-written protobuf. Initializers are named W1, b1, W2, b2 — the same names as the struct fields, so the file is readable in Netron.

1. The Contrast: Computation vs. Inference

Why can a calculator solve arithmetic instantly — yet has no operation for "I loved it"?

Rigid Computation (Pocket Calculator)
((4,812 × 37.5) - 8,941) ÷ 1.25 = ?
Pocket Calculator: ⚡ Solved in 0.00001s: 137,207.2
Human Mind: 🤯 Needs scrap paper, takes 3 minutes!

Computation: A human engineer wrote exact arithmetic rules in code. 100% exact and deterministic.

Messy Inference (AI Model)
"I loved it!" ➔ Good or bad comment?
4-Year-Old Child: ⚡ Answers in 0.1s: "Obviously good!"
Pocket Calculator: 🛑 No language operation — outside its instruction set

Inference: There is no simple hand-written formula that maps arbitrary English to "positive" or "negative". The mapping has to be learned from examples.

The Core Question: Language is open-ended and ambiguous, so a hand-written rule set is impractical to complete. Where does the procedure come from instead? One answer is to learn the mapping from labeled examples — that is Training.

Software that maps messy inputs to decisions.

• A model is not a conscious brain or magic. In this lab it is a mathematical lookup table; larger models are the same idea with many more dials.

• A newly initialized model has a blank slate. It has no learned associations with English, joy, or anger — until training gives it some.

3. Samples: The Historical Ground Truth

Past observations paired with known outcomes.

+ Positive Ground Truth
"The service was great and fast."
- Negative Ground Truth
"The service was terrible and slow."

• Hand-written rules don't cover the variety and ambiguity of natural language at scale, so we supply Training Samples.

• These live as passive, static text files on Disk Storage (SSD) when the power is off.

• On disk, raw files have zero predictive power. They are simply dormant evidence waiting to be processed.

4. Training: Crunching Raw Data into an Artifact

A one-way distillation process that discards the raw text.

Training Job (CPU/GPU)

Burns processing time

Compiled Model in RAM
{ "great": +1, "slow": -1 }
Raw text is discarded!

• Training is not loading: Training is the computation that reads raw sentences, counts clue associations, and produces a tiny compiled dictionary artifact (model.json).

• The Discard Step: Once training is finished, this step discards the raw text. The artifact keeps only the distilled numbers; the original sentences are no longer needed.

5. Inference: Evaluating New, Unseen Inputs

Real-time scoring against active memory in RAM.

New Live Input
"Shipping was incredibly slow."
➔
CPU Checks RAM
Found: "slow" (-1)
➔
Output Decision
100% Negative

• Inference is read-only: The model scores the incoming sentence in milliseconds by checking memory in RAM.

• The Model Does Not Learn During Inference: Testing the sentence does not alter RAM. It is a one-way mathematical calculation.

• Blind Spots: If a customer uses words never observed during training, this model has no learned evidence for them and falls back to 50% — an Out-of-Vocabulary blind spot.
